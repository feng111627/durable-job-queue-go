# durable-job-queue-go

单机本地任务队列：模拟任务的入队、投递、确认与失败重试，让重复投递、并发消费和进程重启后的数据状态都可预期。

## 快速开始

```go
q, _ := queue.Open("/path/to/queue.json", queue.Options{})
defer q.Close()

// 入队（key 为幂等键，可传空串跳过去重）
id, dup, _ := q.Enqueue([]byte("payload"), "order-123")

// 消费：轮询 -> 处理 -> 确认 / 失败上报
d, _ := q.Poll("worker-group", "consumer-1")
if d != nil {
    if err := handle(d.Job); err != nil {
        q.Nack(d.Group, d.Job.ID, d.Token, queue.FailureRetryable, err)
    } else {
        q.Ack(d.Group, d.Job.ID, d.Token)
    }
}

// 查询死信
for _, dl := range q.DeadLetters("worker-group") { ... }
```

## 投递语义

- **至少一次（at-least-once）**：任务被确认前，可能因租约超时、失败重试或进程重启被重复投递；队列保证已确认的任务不再投递、未确认的任务绝不丢失。重复投递场景下“同一任务不被重复执行”需消费方幂等（可配合入队幂等键与业务去重）。
- **租约 + 令牌**：`Poll` 取走任务后进入 `VisibilityTimeout` 租约期，同组内其他消费者拿不到它；租约到期未确认自动回到待投递。每次投递颁发新令牌，旧消费者持过期令牌 `Ack/Nack` 会被拒绝（`ErrStaleToken`），防止重复投递时旧消费者误操作。
- **消费组**：每个消费组独立维护每个任务的投递状态。同组内一个任务同一时刻只投递给一个消费者；不同消费组各自拿到全量任务，互不影响。

## 重试与死信规则

- 失败原因通过 `Nack` 的 `FailureKind` 区分：
  - `FailureRetryable`：按指数退避重新投递，第 n 次失败后等待 `BaseBackoff * 2^(n-1)`，封顶 `MaxBackoff`；
  - `FailureFatal`：不重试，直接进死信。
- 重试上限 `MaxRetries`：投递次数超过 `1 + MaxRetries` 仍失败即进死信。
- 死信按消费组隔离，通过 `DeadLetters(group)` 单独查询，包含任务、累计投递次数、失败原因与进入死信时间；死信任务不再投递。

## 幂等去重与持久化的取舍

- **去重**：`Enqueue` 携带非空幂等键时，同键重复入队返回 `dup=true` 和原任务 ID，不产生新任务。
- **容量受限**：去重记录不超过 `DedupCapacity`。容量满时按插入顺序从旧到新扫描，淘汰第一条“对应任务已在所有已知消费组终结（全部确认或全部死信）且至少被投递过一次”的记录；**仍在等待投递或重试中的任务记录一律不淘汰**；若没有任何可淘汰记录，入队失败并返回 `ErrDedupFull`，由调用方决定稍后重试。该策略确定且可解释，代价是：已终结任务的去重记录被淘汰后，同键再入队会被当作新任务——这是有界去重的固有取舍。
- **持久化**：每次状态变更（入队/投递/确认/失败）后把完整状态快照写入磁盘（临时文件 + rename 保证原子性，崩溃不会留下半个文件）。实现简单、恢复确定，代价是写入放大，适合单机模拟而非高吞吐场景。
- **重启恢复**：重新 `Open` 时加载最后一份完整快照；重启前处于投递中（inflight）但未确认的任务一律回到待投递重新投递，重试次数、退避时间、死信与去重记录原样恢复，不引入重复或错位。

## 本地验证

```bash
go build ./...      # 编译
go vet ./...        # 静态检查
go test -v ./...    # 运行测试，日志可见各业务用例与结果
go test -race ./... # 并发竞争检测
```

测试覆盖的业务场景（`go test -v` 日志中可直接看到）：

| 业务 | 用例 |
| --- | --- |
| 至少一次投递 | 重复入队同一幂等键只入队一次；租约超时未确认的任务被重新投递且旧令牌失效；已确认的任务不再投递 |
| 消费组与并发 | 同组 8 个消费者并发消费 50 个任务、每个任务恰好落到一个消费者；不同消费组各自拿到全量任务 |
| 重试与死信 | 可重试失败按 1s/2s 退避重投、超过上限进死信；不可重试失败直接进死信且可单独查询 |
| 重启恢复 | 重启后 acked 不重投、inflight 重新投递、重试次数与死信完整恢复、去重记录恢复 |
| 去重容量 | 容量满时淘汰已终结任务、不淘汰重试中的任务；无可淘汰记录时返回 `ErrDedupFull` |
